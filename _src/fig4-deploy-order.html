frp 远程访问 · 部署顺序

从零搭这条链路，六个步骤 顺序不能反

每一步只做一件事、只验一件事。上一层的验收命令没跑通，就不要碰下一层 —— 每一层都能独立证明自己是好的，叠起来才有意义。

01
DNS 解析
域名控制台 DNS 面板
执行配 A 记录 / 泛解析
*.example.com A 1.2.3.4
验收dig +short app1.example.com
→ 1.2.3.4
✓ 01 解析确认通了↓ 才轮到开端口
02
安全组放行
云控制台 安全组 · 入站
执行只开这四个端口，其余全关
22 / 80 / 443 / 7000 TCP
验收nc -vz 1.2.3.4 7000
→ succeeded! （从外网机器执行）
✓ 02 外网能连 7000↓ 才去装 frps
03
frps + Caddy
云服务器 /opt/frp
执行入口侧两个容器一起拉起
docker compose up -d
验收curl 127.0.0.1:7500/healthz
→ ok （frps 本机健康）
✓ 03 入口侧自检通过↓ 才轮到 NAT 里的应用
04
应用容器
内网机 ~/apps
执行先让 app1 在本机自己能打开
docker compose up -d
验收curl 127.0.0.1:8080
→ app1 页面
✓ 04 应用自己会响应↓ 才轮到 frpc
05
frpc 拨出
内网机 ~/frp
执行最后才让 NAT 后主动拨出去
docker compose up -d frpc
验收docker compose logs frpc
→ login to server success
→ start proxy success
✓ 05 两条日志都出现↓ 才值得测域名
06
端到端验收
任意机器 手机热点 / 外部笔记本
执行用域名完整走一遍整条链路
curl -I https://app1.example.com
验收HTTP/2 200
→ 证书有效，链路全通
正着做
每层都有独立的证据

六步对应六条验收，每条只回答一个问题。任何一步坏了，停在这一步。

1DNS 返回 IP✓
2外网端口可达✓
3frps 本机健康✓
4app 本机响应✓
5frpc 登录成功✓
6域名返回 200✓
反着做
断链时，五个都是嫌疑人

frpc 日志已经 login success，可 https 还是打不开。没验过的层，全是未知：

DNS 记录对不对？?
安全组开了 7000 吗？?
Caddy 反代配了吗？?
frps 健康吗？?
app1 自己活着吗？?
顺序反了的代价不是搭不起来，是坏了说不清在哪一跳。
自检
开下一步之前，先问三句
1这一步的验收命令是什么？
2它现在能单独跑通吗？
3跑通了，才允许动下一步。
先能单独验，才允许往上叠。
验收命令就是故障切分线：跑通一条，少一个嫌疑人。
6 步 = 6 条验收 —— 每一层都先能独立自证 顺序反了不会搭不起来，只会坏得查不出来 断链时从 ① 重跑验收，第一条失败的就是断点
